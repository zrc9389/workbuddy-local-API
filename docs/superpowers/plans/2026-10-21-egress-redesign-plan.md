# 账号出口页重构开发文档

状态：规划中，尚未修改产品代码。
日期：2026-10-21

## 一、目标

把“账号出口”从账号路由列表改成以订阅节点为核心的工作页：订阅导入、订阅详情、节点列表、缓存延迟和手动刷新集中在同一页面。账号只在用户需要绑定时进入选择流程，不再把 16 个账号作为出口页主体。

核心规则：

- 订阅没有两条限制，可添加 3、4 或更多条；继续遵守后端 16 条、1000 节点、64 MiB provider 存储和 256 个账号绑定上限。
- 进入页面默认读取本机缓存，不下载订阅，不刷新节点延迟，不启动测速任务。
- 节点缓存最长 48 小时；超过 48 小时只标记为“缓存已过期”，是否自动刷新由统一的手动刷新按钮控制，避免登录和切页产生上游请求。
- 点击“刷新节点”才执行订阅刷新与节点延迟测试。刷新期间按钮保持原文字，仅通过边框和文字颜色显示进行中；成功或失败后自动恢复。
- 订阅 URL 默认不出现在普通列表中；用户点击订阅详情组件后，在弹窗中明文展示名称、完整 URL、启用状态、节点数和最近更新时间。完整 URL 只在该弹窗中展示，不写入普通日志。
- 不修改 `internal/metacore` 的第三方内核实现、`third_party/meta` 内核文件或反代内核实现；所有能力通过现有面板 API、缓存策略和前端编排完成。

## 二、当前问题基线

当前出口页仍包含流量统计、实时速率、账号路由列表和账号节点弹窗。订阅管理仍位于系统设置，出口页通过弹窗读取节点并提供手动测试，但节点弹窗仍有“绑定此节点”按钮、过多解释性小字和较大的留白。

当前已有后端能力：

- `GET /panel/api/meta/subscriptions`：读取订阅摘要，默认不回显完整 URL。
- `GET /panel/api/meta/subscriptions?id=<id>&reveal=1`：显式读取完整订阅 URL。
- `POST /panel/api/meta/subscriptions`：新增订阅，或按 `action` 执行 `toggle`、`rename`、`refresh`、`delete`。
- `GET /panel/api/meta/nodes`：读取缓存节点和绑定。
- `GET /panel/api/meta/nodes?subscription_id=<id>`：读取指定订阅的缓存节点。
- `GET /panel/api/meta/tests`：读取上次测速结果，不会主动测速。
- `POST /panel/api/meta/tests`：显式启动一次有界节点延迟测试。
- `POST /panel/api/meta/accounts/{uid}/bind`：绑定账号到节点，成功后需要回读确认。

当前前端主要问题：

- `egress.js` 仍把 `egressAccounts` 作为主视图；需求应改成节点主体。
- 订阅管理 DOM 在系统设置，出口页没有完整订阅管理入口。
- 打开节点弹窗时仍展示“选择账号出口”和账号绑定语义，视觉与用户需要的节点浏览不一致。
- 节点测试入口和缓存时间没有被设计成页面主操作；缓存过期和手动刷新策略未形成统一界面。
- CSS 使用本地字体栈，当前没有真正加载用户希望直接看到的远程字体。

## 三、目标信息架构

桌面布局：

```text
账号出口
┌──────────────────────────────┬──────────────────┐
│ 节点目录                      │ 订阅概览          │
│ [全部] [订阅A] [订阅B]         │ 3 个订阅          │
│ [刷新节点] 上次缓存 03:12      │ [查看订阅详情]     │
│ ┌────┐ ┌────┐ ┌────┐          │ 当前缓存状态      │
│ │节点│ │节点│ │节点│ · 延迟     │ 最近刷新时间      │
│ └────┘ └────┘ └────┘          │                   │
└──────────────────────────────┴──────────────────┘
```

手机布局：

```text
账号出口
[订阅概览] [查看详情]
[全部订阅 ▼] [刷新节点]
缓存时间 / 状态
┌──────────────┐
│ 节点名   42ms │
└──────────────┘
```

节点卡片只保留：节点名称、协议或来源的短标识、延迟、可选的当前账号标记。名称过长时使用截断并保留完整名称的 `title`/无障碍文本；不显示 provider ID、冗余 URL、解释性长句或“绑定此节点”大按钮。

## 四、交互契约

### 4.1 订阅组件

- `subscriptionCount`：显示订阅数量和启用数量。
- `subscriptionDetailButton`：打开订阅详情弹窗。
- 弹窗内每行显示：名称、完整 URL、启用状态、节点数量、缓存更新时间、启用/停用、刷新、改名、删除。
- URL 以普通文本展示，禁止写入浏览器存储和日志；弹窗关闭后从 DOM 清除。
- 删除存在绑定的订阅时保持后端 409，不提供静默直连。

### 4.2 节点目录

- `subscriptionFilter`：切换全部或单个订阅，仅 GET 缓存节点。
- `refreshNodes`：一个统一的手动刷新按钮。实现顺序由后端现有边界决定：按需刷新订阅 provider，再执行有界延迟测试，完成后重新读取节点和测试结果。
- 进入页面、切换筛选、打开详情不调用 POST 测试。
- 延迟显示优先级：最近缓存成功延迟、测试中、超时、失败、未检测。显示缓存时间；不把未检测伪装成 0ms。
- 点击节点卡片进入绑定确认/直接绑定流程。根据用户当前确认，节点卡片不再提供第二个“绑定此节点”按钮；需要避免误触时使用轻量确认，而不是重复按钮。
- 绑定成功必须 GET 节点/绑定回读；失败保留旧绑定。

### 4.3 48 小时缓存

- 缓存元数据至少包含 `refreshed_at`、`expires_at`、`subscription_id`、节点数量和最近测试时间。
- 未超过 48 小时：显示“缓存可用”，只读。
- 超过 48 小时：显示“缓存已过期”，仍展示旧节点，等待用户点击刷新。
- 不在登录 bootstrap、页面切换定时器或普通刷新按钮中自动刷新订阅/节点。
- 服务器端仍可保留 provider 文件和后端状态；48 小时是面板数据 freshness 策略，不修改 Meta 内核生命周期。
- 若现有 `meta/nodes` 响应没有完整缓存时间，优先在面板响应中增加脱敏时间字段，不回显订阅 URL。

## 五、字体方案

用户明确希望直接看到字体效果，不接受“需要本地下载后才可见”。方案采用远程字体 + 本地回退：

- 英文：`Source Sans 3`，作为克制、现代的人文无衬线；中文：`Noto Sans SC`。
- 使用固定版本的 Google Fonts CSS 或自有静态字体源，`font-display: swap`，网络失败时立即使用本地回退。
- CSS 字体声明使用 `Source Sans 3`, `Noto Sans SC`, `Microsoft YaHei UI`, `Segoe UI`, sans-serif。
- 当前页面的 CSP 需要显式允许固定字体源的 `style-src` 和 `font-src`；不能仅添加 `<link>` 后假装已加载。
- 后端响应头位置需先确认；若项目当前没有 CSP header，则在面板静态资源响应层增加最小白名单，不能放开任意外域。
- 字体请求失败不阻塞密码登录、账号同步或出口页。

## 六、拟修改文件

### 必改

- `internal/panel/index.html`：把订阅管理入口和节点目录放进出口页；移除出口页账号路由主体；新增缓存状态、刷新按钮、订阅详情弹窗和紧凑节点目录。
- `internal/panel/assets/egress.js`：改为节点主体；统一缓存读取、筛选、手动刷新、缓存时间显示、节点卡片点击绑定和详情弹窗。
- `internal/panel/assets/styles.css`：出口页非对称布局、节点小方框、订阅详情侧组件、紧凑弹窗、刷新状态和手机单列。
- `internal/panel/assets/config.js`：迁移或提取订阅管理逻辑，避免系统设置继续展示订阅导入入口；保留 API 复用，不保留重复 UI。

### 可能改

- `internal/panel/meta.go`：仅当现有响应无法提供缓存时间、刷新状态或订阅详情字段时，增加面板层字段和受保护的读取接口。
- `internal/metacore/manager.go` / `subscriptions.go`：仅当缓存时间或刷新回读无法在面板层获得时调整业务状态字段；不改内核实现。
- 面板静态资源 CSP/header 生成位置：允许固定字体 CSS 和字体文件来源。

### 测试

- `internal/panel/frontend_egress_redesign_test.mjs`：节点主体、订阅组件、过滤、缓存、手动刷新、无自动 POST、绑定回读、详情清理。
- `internal/panel/meta_test.go`：订阅摘要、显式 URL、节点缓存时间和刷新错误回滚。
- `internal/metacore/subscriptions_management_test.go`：多订阅、绑定保护、刷新失败保留旧数据。
- 浏览器测试：1440、1366、390 视口；字体请求成功/失败；键盘操作；减少动画；无横向溢出。

## 七、明确不改

- 不修改 `third_party/meta`、Mihomo 二进制、Meta 内核实现。
- 不修改 `internal/server` 和反代核心请求逻辑。
- 不在登录时刷新订阅或测速。
- 不把完整 URL 写入普通 API 列表、日志或浏览器持久化。
- 不保留出口页的账号列表作为主内容；账号只作为绑定目标参与交互。

## 八、实施顺序

1. 先冻结现有 API 和缓存字段，补测试夹具。
2. 将订阅导入/详情从系统设置迁移到出口页，删除重复入口。
3. 将出口主内容替换为节点目录，接入全部/订阅筛选。
4. 实现 48 小时 freshness 显示和单一手动刷新入口。
5. 重做紧凑节点卡片与轻量绑定交互，清理冗余提示。
6. 接入远程字体与 CSP 白名单，验证失败回退。
7. 运行 Go/Node/浏览器多视口测试，确认前后端回读。
8. 通过测试后由原有子智能体构建、备份并部署 VM；失败自动回滚。

## 九、验收标准

- 出口页首屏不出现账号路由列表；节点卡片按模块化小方框展示名称和缓存延迟。
- 可以导入至少 4 条订阅；可以查看每条订阅的名称和完整 URL；URL 仅在弹窗中明文显示。
- 页面加载和登录不触发订阅下载或节点测速。
- 缓存未过期时只读；过期显示过期状态但不自动刷新；点击一次刷新完成所有节点刷新。
- 刷新失败保留旧缓存和旧绑定，并给出简短可读状态。
- 节点筛选、节点点击绑定、回读一致；重复点击不会产生重复请求。
- 字体网络可用时页面直接呈现 Source Sans 3 + Noto Sans SC；网络不可用时无布局崩坏。
- 1440/1366/390 视口无横向滚动；所有弹窗可键盘关闭；减少动画有效。
- 全量 Go/Node 测试通过；部署后 VM 服务 active，Meta 内核哈希不变。

# WorkBuddy Local 面板改版设计稿

状态：仅设计与讨论，尚未修改代码、未重启服务、未导入新订阅。
日期：2026-10-20

## 1. 已确认决策

1. 两条订阅可以同时启用，分别刷新、禁用、查看节点；一个账号可以选择任意订阅中的节点。
2. 默认一个账号只绑定一个节点，账号之间允许绑定不同节点。
3. 昼夜切换以 Uiverse 组件为视觉参考：https://uiverse.io/Pradeepsaranbishnoi/strong-treefrog-90。实现为本地可访问组件，不依赖远程页面资源。
4. 任务完成后默认只显示汇总；点击失败数量或失败状态后查看失败详情。
5. 用户提供的 JSON 由后端兼容适配，用户不需要手工改文件。
6. 当前阶段只形成设计文档，不执行实施。

## 2. 当前代码事实

源码根目录是 workbuddy-local。

- internal/metacore 已有 Mihomo 管理、订阅、节点、测试、账号绑定和独立代理入口。
- 面板已有 meta/status、meta/nodes、meta/tests、meta/subscriptions 和账号绑定接口。
- internal/panel/import.go 已兼容对象、数组和部分 Cockpit 导出格式，但用户 JSON 仍需用脱敏 fixture 做字段覆盖测试。
- internal/panel/assets/egress.js 目前把节点测试做成独立弹窗，账号出口也是单独按钮。
- internal/panel/index.html 顶部仍有本机会话和主题按钮，设置页仍有主题选择，概览区目前为空。
- internal/panel/assets/tasks.js 目前会把每个步骤的账号结果直接渲染到页面。
- internal/panel/assets/packages.js 仍显示剩余为零的包；format.js 的 fmtTok 会使用 k/M/B 缩写。
- styles.css 的 shell 使用 max-width 1770px 和 margin auto，是全屏时悬浮导航靠近中间的主要可疑原因。

以上是静态源码结论。白色拖动条的真实来源仍需浏览器检查，可能是根滚动条、内部滚动容器或 resize handle。

## 3. 信息架构设想

~~~text
概览
  账号环形统计 2/3 | 昼夜切换组件 1/3
账号池
  账号身份 | 节点选择器约 1/3 行宽 | 延迟 | 操作

~~~

独立的“节点测试”导航和出口卡片移除。测试能力保留在节点选择器与订阅管理：订阅刷新后可测试新节点，节点列表可按需测试，账号选择时显示最近检测状态。

## 4. 后端数据模型

### 4.1 订阅实体

~~~json
{
  "id": "sub-...",
  "name": "订阅名称",
  "url": "后端保存，不返回浏览器原文",
  "enabled": true,
  "status": "ready",
  "last_refresh_at": "时间",
  "last_error": "",
  "node_count": 5
}
~~~

URL 只由后端处理和保存，不写日志，不在错误消息中回显 token。两条订阅中同名节点也必须用 subscription_id 加 node_id 形成唯一身份。

### 4.2 节点与绑定

节点至少包含 id、subscription_id、name、type、status、delay_ms、tested_at 和 history。状态统一为 untested、testing、ok、timeout、error、disabled。

账号绑定至少包含 uid、subscription_id、node_id、route_id、port 和 updated_at。绑定按账号独立生效；切换只影响新连接，已有连接保持原路由。删除订阅或节点前检查绑定关系，禁止静默直连。

## 5. 后端接口建议

| 能力 | 建议接口 | 目的 |
|---|---|---|
| 订阅列表 | GET /panel/api/meta/subscriptions | 返回两条订阅的脱敏状态 |
| 新增订阅 | POST /panel/api/meta/subscriptions | 接收名称、URL、启用状态 |
| 修改订阅 | PATCH /panel/api/meta/subscriptions/{id} | 修改名称或启用状态 |
| 刷新订阅 | POST /panel/api/meta/subscriptions/{id}/refresh | 下载、解析、原子替换 |
| 删除订阅 | DELETE /panel/api/meta/subscriptions/{id} | 有绑定时返回冲突 |
| 节点列表 | GET /panel/api/meta/nodes?subscription_id=... | 返回节点和延迟 |
| 节点测试 | POST /panel/api/meta/nodes/test | 支持全部、订阅或指定节点 |
| 绑定节点 | POST /panel/api/meta/accounts/{uid}/bind | 返回回读后的 binding |
| 解绑节点 | DELETE /panel/api/meta/accounts/{uid}/bind | 清理账号绑定 |
| 导入预检 | POST /panel/api/accounts/import/preview | 只解析不落盘 |
| 正式导入 | POST /panel/api/accounts/import | 校验后写入 |
| 订阅诊断 | POST /panel/api/meta/subscriptions/diagnose | 分析 HTTP 和格式 |

订阅诊断必须返回状态码、最终 URL、Content-Type、响应类型识别、解析器选择、节点数量、失败位置和建议，不返回敏感正文。这样 search?token 链接失败时，可以区分网页响应、鉴权失败、重定向、格式不支持和节点为零。

## 6. JSON 兼容策略

增加独立输入适配器，避免把兼容逻辑散落到 auth.Parse、handler 和前端。

1. 接受根对象或根数组，识别 account、auth、proxy、realm 等结构。
2. 同时兼容驼峰和下划线字段，例如 enterpriseId/enterprise_id、accessToken/access_token、refreshToken/refresh_token。
3. 统一提取 UID、昵称、realm、访问令牌、刷新令牌、过期时间和代理字段。
4. 导入前检查 UID 唯一性、token、realm、代理 URL 和大小限制。
5. 先完成整批预检，再执行原子写入；失败返回字段级原因。
6. 响应只返回 UID、昵称、状态和错误摘要，不返回 token。

用户附件含真实凭据，文档不复制 token、代理密码或完整内容。实施时使用脱敏 fixture，并增加等价字段结构回归样本。

## 7. 账号行

~~~text
账号身份与状态          节点选择器约 1/3              操作
昵称 / UID / 余额       [订阅 · 节点] 733 ms           禁用 · 删除
~~~

选择器按订阅分组，显示订阅名、节点名和最近延迟。节点后显示未测试、测试中、可用、超时或失败。切换时显示切换中，等待后端绑定回读成功后显示已应用；失败时保留原绑定，不退回直连。

桌面端保持现有行高级别，节点选择区约占一行三分之一。移动端身份区和操作区分两行，节点选择器占满可用宽度。账号行不再以“出口按钮”作为主要入口，也不再依赖独立节点测试模块。

## 8. 概览与主题

概览主区域采用 2fr 1fr，窄屏变为单列。

左侧账号环形统计：圆环按总数、可用、冷却、禁用绘制；右侧依次排列账号总数、可用、冷却、禁用；颜色复用账号池状态色；圆心显示总数；无账号时显示空状态；统计来自后端聚合，不按分页计算；同时提供文本标签。

右侧昼夜组件：使用 Uiverse 的太阳、月亮和昼夜层次感。整个组件是真正的 button，具备 aria-label、aria-pressed 和键盘操作。点击位置作为动画圆心，用圆形 clip-path 或 View Transitions 让主题逐渐扩散。prefers-reduced-motion 时直接切换。只保留 dark/light 两态，设置页和顶部旧主题控制删除。

主题状态仍可保存到后端，但不保留 auto 三态，避免逻辑重复。Uiverse 页面当前只确认了组件信息，实施时按其视觉重新组织本地 HTML/CSS，并沿用现有 CSS 变量。

## 9. 任务结果

任务运行中，每个步骤只显示整体进度、完成数、失败数和当前阶段，默认不渲染所有账号。失败进度条使用红色，成功使用绿色，执行中使用品牌色。

任务结束后显示完成、失败、跳过数量。失败数量做成可点击按钮，带 aria-controls 和“查看失败详情”标签。点击后打开右侧抽屉或模态，仅列失败账号、失败原因、发生时间和可用的重试入口。全部成功时不渲染空失败区；失败详情使用分页，防止大账号池撑大 DOM。

## 10. 积分构成

- remain 小于等于 0 的积分包不出现在积分列表、到期分布和账号包明细。
- 账号总余额为 0 时显示账号汇总，但显示“暂无剩余积分包”，不显示已用完空包。
- 积分使用独立 formatInteger，显示 12500 或 12,500，禁止 12.5K。
- Token 和流量可以继续缩写，但不能复用积分格式化器。
- 未知余额显示未知，不能转换为 0。

## 11. 全屏、移动端和滚动条

全屏桌面将 shell 改为 width 100%、max-width none，保留安全内边距；导航锚定视口侧边，主内容使用剩余宽度；网格统一使用 minmax(0, 1fr)，长节点名允许断行。

手机端使用紧凑顶部或固定底部导航，预留 safe-area-inset-bottom；账号行两行布局；概览变单列；抽屉和模态限制高度并让内容独立滚动；关键状态提供文字，不依赖 hover。

先确认白色拖动条来源，再处理。不要用 overflow hidden 粗暴隐藏滚动能力。根滚动条和内部滚动区使用主题色 scrollbar-color；模态只锁背景滚动，不能锁模态内容滚动。

## 12. 额外前端建议

1. 订阅导入增加预检步骤，显示类型、节点数、协议和错误位置，再允许正式保存。
2. 订阅列表逐条显示启用开关、刷新时间、节点数和失败原因。
3. 节点选择器提供仅显示可用节点和按延迟排序，筛选放在弹层内，避免增加账号行高度。
4. 节点状态显示更新时间，避免把旧延迟当实时延迟。
5. 异步操作统一处理加载、成功、失败、超时，防止重复提交。
6. 补充键盘焦点、Escape 关闭、焦点回收和屏幕阅读器标签。
7. 新颜色全部走现有 CSS 变量和账号池状态色。
8. 接口失败后清理旧数据，不能用旧数据冒充最新状态。
9. 前端错误记录只保存错误类型和接口路径，不记录 token、订阅 URL 或响应正文。

## 14. 验收门槛

后端：用户 JSON 无需手工修改即可预检和导入；两条订阅可同时启用、分别刷新和禁用；每账号一个有效绑定；测试失败不直连；敏感 URL、token、密码不进入普通响应和日志。

前端：概览为 2/3 加 1/3，移动端无横向溢出；账号行节点区约占三分之一；任务完成不默认显示全部账号；点击失败可看详情；积分不显示零包且使用完整数字；旧主题控制和独立节点测试入口移除；全屏导航靠边；手机导航不遮挡；滚动正常。

测试：Go 覆盖 JSON 适配、双订阅、绑定冲突、诊断分类和脱敏；Node 覆盖环形统计、主题切换、积分过滤、完整数字、失败详情折叠；浏览器覆盖桌面宽屏、1366、390、双主题、减少动画和键盘路径。

## 15. 实施前待定

- 订阅名称手填，还是从域名生成默认值。
- 同名节点是否始终显示“订阅名 · 节点名”；建议始终显示。
- 检测默认刷新后自动，还是用户点击；建议只检测新节点和过期节点。
- 失败详情是否允许单账号重试，取决于后端任务接口。
- 主题扩散动画建议 420ms，减少动画时直接切换。
- 环图分段是否点击跳转账号池；建议允许，但不让它成为唯一筛选入口。

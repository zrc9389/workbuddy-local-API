# 后端 API、数据生命周期与模块依赖审计

日期：2026-10-27
范围：候选工作区 `work/workspace`。本文件记录确认稿约束、现有代码审计发现和实施边界，不代表尚未通过的测试已经完成。

## 确认的系统约束

- WorkBuddy 仅本机访问，Linux 优先；首次设置非空管理密码，登录会话与 CSRF 防护继续保留。聊天接口不要求新增 API key。
- 当前几何单页是主 UI 和主要 API 契约；后端调整需维持已使用的端点与字段，只有契约测试或必要兼容修复允许带动小幅前端调整。
- 删除账号先建立 admission fence，拒绝该账号的新任务和请求；等待已经开始的上游请求及任务结束后再执行清理。凭证进入隔离目录保留 7 天。移除账号的 Meta 绑定及账号级 transport/连接缓存；保留订阅与节点数据。
- 请求归档和 usage 按事件时间滚动保留 24 小时。清理由应用执行，不以文件修改时间代替业务事件时间。
- 请求体默认完整转发，不静默截断。优先流式与有限内存；只有明确配置保护上限时才按配置拒绝超限请求。容量上限开关不得导致部分请求已经发送到上游后才拒绝，也不能把 spool 写成零容量。
- 音频允许主流格式；暂不设置固定容量上限，若启用容量保护应为明确可配置项。
- Meta 出口默认每账号隔离；只有用户明确选择时才共享。代理/节点故障必须 fail-closed，不回落直连。订阅仅接受 HTTP/HTTPS，出口设置必须以真实请求验证。
- 全局刷新刷新余额、用量、错误记录和积分包，不刷新 Meta 节点。任务支持手动与定时；失败结果需可见。令牌错误和节点超时不可作无意义重试。
- 启动动画目标 8 秒，硬上限 20 秒。自动更新暂不实现，API 必须返回 HTTP 501，不得假报成功。

## 模块边界与依赖方向

```text
cmd/server（配置、装配、启动/退出生命周期、回环监听）
  ├─ localauth / session（本机管理身份、会话与 CSRF）
  ├─ panel（受管理会话保护的 JSON API 与静态前端）
  ├─ server（聊天/Responses 协议、准入、spool、转发）
  ├─ maintenance / tasks（作业编排与状态）
  ├─ pool（账号资格、冷却、余额保护、选号）
  ├─ upstream（所有上游网络访问和账号出口租约）
  ├─ metacore（订阅、节点、账号绑定、出口进程生命周期）
  └─ usage / reqlog / conversation / spool（各自数据所有权和留存）
```

- `cmd/server` 负责依赖注入与生命周期，不在业务包中另开监听器或绕过统一身份边界。
- `panel` 将 API 意图映射为有所有权的服务调用；不得直接暴露 Meta controller 凭据、账号 token 或绕过 CSRF 的写接口。前端是消费者，不是数据来源。
- `pool` 只决定账号是否可用及选择策略；`upstream` 执行网络请求，并持有按账号隔离的 transport/egress 租约。transport 缓存失效和 Meta 解绑应经明确接口联动。
- `metacore` 拥有订阅、provider、节点与绑定关系。解绑账号只移除绑定和账号路由，不删除用户导入的订阅节点。代理变更失败需回滚持久配置和运行路由。
- `maintenance`/`tasks` 负责并发与结果状态，任务执行通过统一上游服务。删除账号需要 UID 级 fence、等待该 UID 运行任务；不能因为别的账号有任务而阻断删除。
- `reqlog` 拥有请求明细及账号删除索引；`usage` 拥有汇总桶；`conversation` 拥有历史档案；`spool` 拥有待发送请求及不确定执行记录。账号删除不得把这些互不归属的数据混成昵称/UID 前缀扫描。

## 数据生命周期

| 数据 | 所有者 | 正常生命周期 | 删除账号时 |
|---|---|---|---|
| 账号凭证 | auth 文件存储 | 账号存在期间 | fence 后移入隔离区，至少 7 天后清理；隔离路径/时间应能恢复审计 |
| 请求日志 | `reqlog` | 按事件时间保留 24 小时 | 用不可逆 account reference 精确删除；旧数据若无安全关联字段应停止并报告，不能猜测匹配 |
| 用量 | `usage` | 按时间桶滚动保留 24 小时 | 按 UID 删除并保持持久层回滚语义 |
| 会话/历史档案 | `session` / `conversation` | 现有独立保留规则 | 不具账号归属时不得全局清空；仅清理可证明属于目标账号的记录 |
| spool 请求 | `spool` | 按执行状态保留；unknown 不自动重放 | 先排空目标账号已经发出的工作；未发出任务可取消；unknown 保留核查线索 |
| Meta 订阅/节点 | `metacore` | 用户配置保留 | 只删除账号绑定、账号出口 transport/连接缓存；节点与订阅保留 |
| 缓存/transport | 对应服务 | TTL/LRU 或配置变更失效 | 使目标账号缓存失效，不误伤其他账号 |

## API 契约验收面

1. 从 `internal/panel/assets/*.js` 实际调用提取 URL、HTTP 方法、请求字段、响应字段；测试只断言当前几何单页真实使用的契约，避免为已移除页面重建旧 API 期望。
2. 认证边界分别验证：未登录写接口拒绝；登录后写请求要求 CSRF；读取端点不泄露 token、代理密码或 Meta secret。
3. 数据展示验证真实来源：空值/未知值不得合成金额、节点延迟、积分包或错误日志。刷新操作只能触发约定刷新集合。
4. 错误语义验证账号删除中的等待/冲突、任务失败字段、Meta 订阅 URL 协议校验和更新接口 501。

## 交付门禁

- 对删除、准入、认证或上游重试等行为变更，运行对应 Go 包测试；前端契约变化运行相关 Node 套件。最终至少执行 `go test ./...`、相关 `node --test`、`go vet ./...`、候选普通与 `no_logs` 构建，以及黑盒回环/认证/CSRF/501 检查。
- 报告只列本轮实测结果，并保留未完成环境验收（真实订阅、真实上游、长期负载等）的边界。不得将既往候选哈希当作当前工作区二进制证据。

## 第二阶段请求流证据（2026-10-28）

- Chat 请求体路径：`handler.admit` 先做并发/工作预算准入；未受压的小请求保持内存流，受压请求才进入 `spool.Store.Stage`；`chatCompletions` 对大请求通过 `RequestPayload.OpenReader` 逐次从私有文件直传上游，完成后删除临时文件。
- Responses 适配路径此前在 admission 已可能落盘后又对 `r.Body` 调用 `io.ReadAll`，造成大请求再次完整聚合到堆内存；现改为直接 `json.Decoder` 从已准入 body 解码，并校验尾随 JSON 和显式 body 上限。
- Responses SSE 事件写入此前吞掉客户端写失败；现记录首个写错误，并在完整事件流写完后才提交 pressure spool receipt。客户端断开时不把可能已发送的请求伪装为已提交。
- upstream Chat SSE 使用请求 context、响应头超时和流中 idle 监控；维护类 billing 重试仅对明确 5xx 服务错误重试，超时、传输、认证和业务错误不重试。


## 第三阶段 Meta 内核与每账号出口核验（2026-10-28）

- 订阅地址校验现在接受 `http` 和 `https`，默认端口分别为 80/443；仍拒绝凭据、片段、非公网 IP、localhost、保留地址、非默认端口、过长 URL。下载器禁用环境代理，限制 DNS 解析、重定向、响应头、4 MiB 响应体和 20 秒总超时；刷新失败保留旧 provider/节点状态。
- Meta 配置提交先验证核心配置，再回读 provider 节点、每账号 selector 当前值和本地监听认证，失败回滚旧配置；账号删除只移除绑定和账号出口缓存，保留订阅节点。真实内核双节点出口测试默认跳过，需 `META_REAL_TEST=1`，因此不能宣称公网出口已验收。
- upstream transport 按客户端、基础 transport、账号 UID 和代理配置哈希隔离，TTL/LRU 清理只关闭目标缓存；显式代理配置无效或连接失败时返回错误，不回落直连。修复了租约获取后重新选择账号 transport 的竞态，并禁止已绑定 Meta 账号通过普通代理接口改写/清空出口，必须先解绑。
- 现有测试覆盖本地双节点代理客户端、绑定回滚、订阅刷新失败保留、transport fail-closed 和缓存隔离；尚缺完整 `server→pool→upstream→Meta` 的真实内核交错测试和公网出口验证。

### 内存测量口径与限制

第二阶段 8 MiB×8 测试通过，但它采样的是包含测试夹具的单进程总量：heap 峰值约 182,108,176 字节，RSS 峰值约 269,131,776 字节，最终 spool jobs/bytes 为 0；没有空闲基线、每请求增量或临时文件峰值，不能作为生产多账号保证。审计确认 Responses 适配器、严格历史校验和测试夹具仍可能完整解码/复制 JSON，当前不能证明内存与请求大小无关。后续应在独立进程使用分块生成/消费夹具，分别记录空闲、heap/RSS 峰值与 GC 前后、spool 和临时文件字节，并拆分 Meta 代理开关场景。

## 第四阶段独立进程测量（未完成）

每个场景启动独立服务进程，采用分块生成和完整请求哈希；测试工作预算为 16 GiB，本地 HTTP 代理不是 Meta。Chat 直连及本地代理各 40/40 场景成功；Responses 直连及本地代理各 24/40 成功，32/128 MiB 的 16 个场景在上游处理后返回 507。128 MiB、8 并发、本地代理流式场景采样 heap 峰值 8,794,704,672 字节，工作集峰值 8,820,592,640 字节。采样可能漏峰，不能将这些数据视为默认配置或真实出口结果。

压力 spool 重复落盘和 Responses 克隆重复分配已减少，但严格历史、模型探测和 Responses 整体 JSON 解码及响应聚合仍待解决。未知长度、多模态、大响应和生产程序独立进程仍需覆盖；在内存目标及回归达标前，不进入真实 Meta 验收。
